# 图书借阅系统

本项目是“微服务开发与实践”课程持续演进的唯一项目，复用第一次作业创建的公开仓库。系统围绕图书、读者、借阅、预约和罚款管理展开，先规划并实现单体应用，再根据课程进度逐步加入数据库持久化和微服务能力。

> 当前阶段：第三周 Spring Boot 起步。`monolith/` 中已有可运行的 Spring Boot 工程，只提供问候接口和健康检查；下文的业务功能仍是规划，尚未实现。

## 运行说明

### 环境要求

- JDK 25（`java -version` 显示 25）
- Maven：使用工程自带的 Maven Wrapper（`./mvnw`，会自动下载 Maven 3.9.x），无需单独安装
- Spring Boot 4.0.8，包名 `com.zjgsu.wch`，配置文件为 `monolith/src/main/resources/application.yml`

### 启动与测试

```bash
cd monolith
./mvnw test              # 运行 contextLoads 启动测试
./mvnw spring-boot:run   # 启动应用，默认端口 8080
```

Windows 使用 `mvnw.cmd test` 和 `mvnw.cmd spring-boot:run`。

## 业务背景

面向小型图书馆的日常借阅管理，解决人工记录图书借还时容易出现的库存不清、借阅记录难以追踪、预约顺序不明确和逾期费用统计不便等问题。系统统一记录馆藏、读者、借还、预约和罚款信息，帮助读者了解图书是否可借，帮助管理员处理借还和异常情况。

## 目标用户与项目目标

| 用户角色 | 主要需求 | 计划提供的能力 |
| --- | --- | --- |
| 读者 | 查找图书、了解可借情况、查看借阅期限 | 图书查询、个人借阅记录、预约及取消预约、罚款记录查询 |
| 图书管理员 | 管理馆藏、办理借还、处理预约和逾期 | 图书及馆藏副本管理、读者管理、借出与归还登记、预约分配、罚款登记与缴纳确认 |
| 系统管理员 | 管理工作人员账号和访问权限 | 工作人员账号管理、角色分配、系统基础配置 |

项目目标是形成一条可追踪的“查询—借阅—归还”业务链，并在无可借副本时支持预约，在逾期归还时支持罚款处理。适用场景为单个小型图书馆，不包含跨馆调拨。

## 功能模块

| 模块 | 具体功能 |
| --- | --- |
| 图书管理 | 维护书名、作者、ISBN、分类等书目信息；维护馆藏副本及可借、已借出、待取书等状态；按书名、作者、分类查询；查看可借数量 |
| 读者管理 | 管理读者资料和账号状态；查看个人借阅、预约和罚款记录；停用账号时限制新增借阅与预约 |
| 借阅管理 | 管理员选择读者和可借副本办理借出；记录借出日期和应还日期；归还时更新借阅记录和副本状态；查询当前及历史借阅记录 |
| 预约管理 | 没有可借副本时按书目预约；按预约时间排队；读者可取消预约；副本归还后分配给队首读者并记录取书期限；逾期未取则释放副本并继续处理下一位预约 |
| 罚款管理 | 归还时依据逾期天数生成罚款；查看未缴和已缴记录；管理员确认线下缴纳后更新状态，防止同一次归还重复生成罚款 |
| 账号与权限管理 | 区分读者、图书管理员和系统管理员的操作权限；后续加入登录认证和工作人员账号管理 |

书目表示一种图书，馆藏副本表示可实际借出的每一本书。预约针对书目，借阅针对具体副本，以支持同一种书有多本馆藏的情况。

## 核心业务流程

### 图书借阅与归还

1. 读者查询图书，查看是否有可借副本。
2. 有可借副本时，由图书管理员核对读者账号状态并办理借出，生成借阅记录和应还日期，将副本标记为已借出。
3. 没有可借副本时，读者提交预约，按提交时间进入队列。
4. 读者归还图书，管理员登记归还，结束对应借阅记录。
5. 若逾期，系统根据应还日期与归还日期计算罚款，生成未缴记录；管理员收到线下缴款后确认已缴。
6. 若存在有效预约，归还副本分配给队首读者并进入待取书状态；该读者在期限内取书时，管理员办理新的借阅。若无人预约，副本恢复可借。
7. 预约读者取消或逾期未取时，释放其分配；有后续预约则继续分配，否则恢复可借。

### 初步业务规则

- 初期每位读者最多同时借阅 5 本书，借期 30 天。
- 初期逾期罚款为每天每本 0.5 元，不足一天的计算口径以自然日日期差为准；未逾期不产生罚款。
- 每位读者对同一书目最多保留一个有效预约，预约分配后的取书期限为 3 天。
- 已分配给预约读者的副本，在预约释放前不能借给其他读者。
- 罚款采用线下缴纳、管理员确认的方式，初期不接入支付平台。

上述数值是项目初步设定，后续实现时可作为配置项调整。

## 当前范围与暂不实现的内容

第二周完成选题和功能规划，第三周搭建了 Spring Boot 工程骨架。后续初期采用单体应用，围绕单馆的图书查询、读者管理、借还登记、预约排队和罚款记录实现最小完整业务闭环。

暂不实现跨馆调拨、图书采购、电子书阅读、个性化推荐、在线支付、复杂罚款减免及多渠道通知。暂不引入服务拆分，先完成基础业务与数据库持久化。

## 后续演进方向

| 方向 | 对应业务与计划 |
| --- | --- |
| 数据库持久化 | 保存书目、馆藏副本、读者、借阅、预约和罚款记录，建立关联关系 |
| 认证与权限 | 加入登录认证，限制读者访问自己的记录，区分馆藏操作与系统管理权限 |
| 服务拆分 | 在单体业务稳定后，按图书、读者、借阅等业务职责评估拆分；预约与罚款是否独立拆分依据实际复杂度决定 |
| 消息 | 在图书归还及预约分配后产生事件，用于异步通知预约读者；逐步增加到期提醒 |
| 事务与并发 | 保证借出时借阅记录与副本状态一致，避免同一副本被同时借出；归还、罚款生成及预约分配保持一致；拆分后再学习跨服务事务处理 |
| 监控 | 记录接口耗时、错误和关键业务日志，观察借还及预约处理情况 |
| 部署 | 先实现本地可重复运行与验证，再学习 Docker、Compose 和课程要求的部署方式 |
